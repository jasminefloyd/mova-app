| `/api/calendar-sync` | Every five minutes | Run approved calendar synchronization. |
| `/api/reports-refresh` | Daily at 05:17 UTC | Refresh report aggregations. |

Confirm plan support, active schedules, invocation secrets and current ownership. The checked-in routes use `CRON_SECRET` and service-side configuration. Edge job handlers also check `MOVA_JOB_DISPATCH_SECRET` and `MOVA_JOB_WORKER_SECRET`. Include any Mova-specific scheduler or webhook seen only in the live catalog. Prepare the target with external side effects controlled. During transition, assign one authoritative writer or worker per stream. Define a Mova-specific source write fence with coverage for stale clients and direct project endpoints, including guest writes. A Vercel environment change by itself leaves those source endpoints reachable. Rehearse the fence, its read behavior, and the response users see, while confirming other products can still write to the shared project. ## 7. Open decisions and approval points

Before provisioning, approve the project model, organization, access, region, plan, budget and environment constraints. Before importing data, approve the schema and disposition manifests, identity transfer, and artifact handling. Before routing production traffic, approve the provider and flag configuration, reconciliation evidence, source fence and rollback plan. Approve source data retirement separately after the rollback window.

| Decision | Proposed planning default | Approver or evidence |
| --- | --- | --- |
| Project model and ownership | Dedicated Supabase project for Mova's database, Auth, Storage and Edge, retaining existing web hosts. | Product owner and platform owner confirm organization, access, region, billing plan and budget. |
| Baseline and data load | Use reconciled Mova-only schema and row manifests. Rehearse scoped import locally before production work. | Database owner signs off on live-catalog provenance, exact migration baseline and compatible versions. |
| Auth continuity | Preserve approved users and UUIDs, issue new sessions, and rehearse admin MFA continuity or re-enrollment. | Auth owner approves identity filter, OTP delivery/abuse settings and recovery access. |
| Historical, demo and transient rows | Preserve operational history, consent and financial reconciliation state. Explicitly approve retention, demo scope, archives and queue actions. | Product owner plus data, privacy and provider owners as applicable. |
| Providers and flags | Re-enable only services with existing approval, verified source configuration and signed-off destination validation. | Integration owners approve their endpoint transition, credentials and any reconnect or user communications. |
| Cutover and retirement | Agree on a brief Mova write pause and final delta if the rehearsal shows it meets the business window. Keep the shared source available for other products and documented rollback. | Product and incident owners approve downtime, rollback, retention and later source cleanup as separate actions. |

The implementation record should hold one entry per destination setting or integration with its owner, configuration surface, approved value or secret reference, application consumer, verification evidence, and cutover or rollback dependency. Record the approved deployment revision, Go/No-Go approver, and exception owners in the same record.
